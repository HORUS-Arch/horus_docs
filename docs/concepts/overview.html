Architecture overview#

HORUS is to human-interacting robotics what nav2 is to mobile navigation: a set of servers that host plugins, behavior trees that are data, a lifecycle manager that brings the system up in order, and actions between the brain and the servers. The real-time loop is ros2_control.

Four ROS 2 building blocks#

  • Lifecycle nodes: configure (read parameters, load plugins, connect) is separate from activate (start publishing).

  • Plugin servers: a server owns the loop and the ROS interfaces; a plugin owns only its algorithm.

  • Actions: long tasks with feedback and cancellation (ExecuteBehavior, Calibrate).

  • Components: every C++ node runs as its own process or composed into one.

Rules that hold everywhere#

  • The core never depends on a device or a sensor; they depend on the core (see Add a device).

  • Topics are named /sensors/<name> (raw), /human/<name> (processed), /horus/<node> (system), plus the robot’s own ros2_control topics.

  • Idle means silent: nothing drives the device unless a behavior is running.

  • One controller runs for the whole session; controllers are never switched by a tree.
