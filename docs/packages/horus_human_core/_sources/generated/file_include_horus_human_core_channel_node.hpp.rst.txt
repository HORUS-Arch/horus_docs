Detailed Description
--------------------

Everything is configured from YAML:

channels: [right_upper_leg, right_lower_leg] # unit names (segments, sides, muscles, ...) right_upper_leg.topic: /sensors/imus_a/sensor_0/imu calibration.plugin: horus_human/ImuStaticPose # "" = no calibration subject_id: s01 # set before configure -> latest files auto-load data_root: ~/horus_data mode: calibrated # calibrated | conditioned | bypass (runtime-settable)

Output mode: ``calibrated`` = conditioning + calibration (default); ``conditioned`` = the node's own conditioning only (filtering, envelope), no calibration; ``bypass`` = the raw input republished untouched. Calibration windows always collect conditioned data, whatever the mode.

Lifecycle: configure reads the YAML, loads the plugin, creates the outputs and auto-loads the subject's latest calibration files; activate subscribes to every channel and starts publishing; deactivate stops. Interfaces (all under the node's name):

~/calibrate horus_msgs/action/Calibrate collect + compute (active only); result pending ~/save_calibration horus_msgs/srv/SaveCalibration write pending results for a subject ~/load_calibration horus_msgs/srv/LoadCalibration apply a file, or the subject's latest /diagnostics per-node status: which channels are calibrated, from which file

A derived node only declares its outputs, publishes corrected samples, and may add its own conditioning step (filtering, envelope) that runs before calibration.

Threading: subscription callbacks, services and the calibration thread share one mutex that guards the plugin and the calibration bookkeeping.
