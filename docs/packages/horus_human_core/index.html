README

horus_human_core

The framework behind HORUS’s human-processing nodes. It holds everything a stage-1 (conditioning) node shares, so a concrete node only declares its outputs:

  • CalibrationPlugin<MsgT>: the pluginlib base every calibration algorithm implements (begin / add / finish / load / apply). The algorithm is chosen in YAML (calibration.plugin), so swapping it never touches node code.

  • CalibrationStore: the on-disk calibration files, <data_root>/subjects/<subject>/calibration/<node>/<unit>_<YYYYmmdd_HHMMSS_mmm>.yaml. Every save is a new file; the newest file of a unit is its latest.

  • ChannelNode<MsgT>: a lifecycle node with N named channels of one message type. It owns the subscriptions, the Calibrate action, save/load, auto-loading the subject’s latest files on configure, and diagnostics.

Dependencies

rclcpp, rclcpp_lifecycle, rclcpp_action, pluginlib, diagnostic_updater, horus_msgs, yaml-cpp.

Writing a new node

Derive from ChannelNode<MsgT>. Implement configureOutputs, activateOutputs, cleanupOutputs and publish, and optionally validateChannel and condition (filtering applied before calibration). See horus_human for three examples.

Tests

test/test_calibration_store.cpp (gtest): layout and content, latest-of-exact-unit, foreign-file rejection.
