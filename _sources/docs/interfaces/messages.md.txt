# Messages, services and actions

Generated from the interface files by `scripts/gen_messages.py`; do not edit by hand.

Standard ROS 2 messages are used wherever one exists (`sensor_msgs`, `diagnostic_msgs`, `std_srvs`, `lifecycle_msgs`, `trajectory_msgs`). `horus_msgs` holds the framework's own interfaces; `human_msgs` holds neutral human-state messages that sensor repositories can use without HORUS.

## horus_msgs actions

### Calibrate

Run a calibration on a HORUS processing node (horus_imu, horus_insole, horus_emg, ...). The node collects data for `duration` seconds and computes the calibration with its configured plugin; the result stays PENDING in the node until ~/save_calibration writes it for a subject.

**Goal**

| Field | Type | Meaning |
|---|---|---|
| `unit` | `string` | channel to calibrate (a segment, a muscle, a side); "" = all channels at once |
| `duration` | `float32` | seconds of data to collect (0 = the plugin's default) |

**Result**

| Field | Type | Meaning |
|---|---|---|
| `error_code` | `uint16` |  |
| `error_msg` | `string` |  |
| `units` | `string[]` | units that were calibrated (pending save) |
| `summary` | `string` | short human-readable result, e.g. "mvc 0.42 mV" |

Constants: `NONE = 0`, `UNKNOWN = 1100`, `UNIT_NOT_FOUND = 1101`, `NOT_ACTIVE = 1102`, `NO_DATA = 1103`, `CALIBRATION_FAILED = 1104`

**Feedback**

| Field | Type | Meaning |
|---|---|---|
| `unit` | `string` | unit being collected |
| `progress` | `float32` | 0.0 .. 1.0 |
| `message` | `string` |  |

### ExecuteBehavior

Run a named generator behavior (home / sit / stand / walk / follow_trajectory / ...) on the generator_server. The name selects a generator (+ params) from the server's `generator_plugins`; finite behaviors (sit/stand/home) complete when their generator finishes, continuous ones (walk) run until canceled. Long-running, with feedback + cancel.

**Goal**

| Field | Type | Meaning |
|---|---|---|
| `behavior` | `string` | behavior name (key in the server's `generator_plugins`) |
| `parameters` | `rcl_interfaces/Parameter[]` | optional per-goal overrides of the generator's `<name>.*` params |

**Result**

| Field | Type | Meaning |
|---|---|---|
| `error_code` | `uint16` |  |
| `error_msg` | `string` |  |

Constants: `NONE = 0`, `UNKNOWN = 800`, `BEHAVIOR_NOT_FOUND = 801`, `BEHAVIOR_FAILED = 802`

**Feedback**

| Field | Type | Meaning |
|---|---|---|
| `progress` | `float32` | 0.0 .. 1.0 (finite behaviors); ~0 for continuous |
| `state` | `string` | human-readable phase ("standing up", "walking") |

### Optimize

Run a human-in-the-loop optimization of a behavior's parameters. The optimization server proposes candidates, applies each to `behavior`, collects CostSample's for `cycles_per_candidate` cycles and iterates until the optimizer converges, `max_candidates` is reached, or the goal is canceled.

**Goal**

| Field | Type | Meaning |
|---|---|---|
| `behavior` | `string` | generator behavior whose parameters are optimized |
| `optimizer` | `string` | optimizer plugin name (key in the server's `optimizer_plugins`) |
| `cost` | `string` | cost plugin name (key in the server's `cost_plugins`) |
| `cycles_per_candidate` | `uint32` | cost samples averaged per candidate (0 = server default) |
| `max_candidates` | `uint32` | stop after this many candidates (0 = optimizer decides) |

**Result**

| Field | Type | Meaning |
|---|---|---|
| `error_code` | `uint16` |  |
| `error_msg` | `string` |  |
| `best` | `Candidate` | best candidate found |
| `best_cost` | `float64` |  |
| `results_path` | `string` | where the full history was saved |

Constants: `NONE = 0`, `UNKNOWN = 1000`, `BEHAVIOR_NOT_FOUND = 1001`, `OPTIMIZER_NOT_FOUND = 1002`, `COST_NOT_FOUND = 1003`, `OPTIMIZATION_FAILED = 1004`

**Feedback**

| Field | Type | Meaning |
|---|---|---|
| `current` | `Candidate` | candidate being evaluated |
| `cycles_done` | `uint32` | cost samples collected for it so far |
| `best` | `Candidate` | best so far |
| `best_cost` | `float64` |  |

### SupervisorState

The supervisor's global mode (latched, published on every change). A mode answers one question: who may move the device right now? Safety events always win: an emergency stop, a fault of a critical device or a lost operator drive the supervisor to EMERGENCY_STOP from any mode.

| Field | Type | Meaning |
|---|---|---|
| `mode` | `uint8` |  |
| `previous_mode` | `uint8` |  |
| `mode_name` | `string` | "RUN", ... |
| `reason` | `string` | why the last transition happened |
| `tree` | `string` | tree running for this mode ("" = none) |
| `since` | `builtin_interfaces/Time` | when the current mode was entered |
| `faults` | `string[]` | critical sources in ERROR / STALE (block RESET) |
| `warnings` | `string[]` | non-critical sources in ERROR / STALE, or any source in WARN |
| `operator_connected` | `bool` | operator heartbeat alive (true when heartbeat is disabled) |
| `protocols` | `string[]` | registered tree ids the operator can START |

Constants: `INIT = 0`, `STANDBY = 1`, `RUN = 2`, `MANUAL = 3`, `RECOVERY = 4`, `EMERGENCY_STOP = 5`

### SessionControl

The session: which subject is selected, and whether a trial (recording) is open. SELECT pushes the subject to every HORUS sensing node, which loads its newest calibrations. START opens a trial for the selected subject (or `subject_id`); STOP closes it. With `record: per_run` the session also opens a trial when the supervisor enters RUN and closes it back in STANDBY.

**Request**

| Field | Type | Meaning |
|---|---|---|
| `command` | `uint8` |  |
| `subject_id` | `string` | SELECT: the subject ("" = none); START: optional, selects it first |
| `topics` | `string[]` | START: optional topics to record (empty = the recorder's configured set) |

Constants: `START = 0`, `STOP = 1`, `SELECT = 2`

**Response**

| Field | Type | Meaning |
|---|---|---|
| `success` | `bool` |  |
| `message` | `string` |  |
| `trial_id` | `string` | set on START |
